# Phase 3b — React 17 to 19: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade React 17 → 19 and rewrite the eight `react-test-renderer` suites, without moving a single number the calculator produces.

**Architecture:** `react-router-dom` stays on 5 — that is #49. The eight legacy snapshot suites are migrated **after** React is upgraded, not during, because `react-test-renderer@19` exists and lets the whole suite stay green through the version bump. That ordering means a moved number has one plausible cause at every step.

**Tech Stack:** React 19 · `@testing-library/react` 16 · Vite 4 · Vitest 1 · TypeScript 5 · Node 22

**Spec:** `docs/superpowers/specs/2026-08-30-icl-calc-modernization-design.md`

**Issue:** #48 · epic #53

## Global Constraints

- **`src/data.csv` and `src/golden/expected.json` must not change.** CI enforces both: `golden-master-guard` fails any PR touching either outside an `oracle/*` branch.
- **`react-router-dom` stays on 5.** Upgrading it is #49. If something appears to require it, stop and escalate rather than widening the phase.
- **This phase regenerates every snapshot in the repository.** That is expected and is the whole reason the golden master was built first. Snapshot churn is where a real regression hides, so every regenerated snapshot must be *explained*, not merely accepted.
- Build output stays in `build/`; `base` stays `/icl-calc/`; `build.target` stays pinned at `['chrome87','edge88','firefox78','safari14']` — that floor was an owner decision, not a default.
- Conventional commits. Work in the existing worktree. Do not merge; the human merges.

## What the migration surface actually is

Scanned before planning, so nobody has to rediscover it:

| Concern | Status |
|---|---|
| `defaultProps` on function components (removed in 19) | **None in `src/`** |
| `propTypes` (removed from the React package) | **None in `src/`** |
| String refs, `createFactory`, `findDOMNode` | **None** |
| `ReactDOM.render` | `src/index.tsx:23`, `src/App.test.tsx` |
| `unmountComponentAtNode` (removed in 19) | `src/App.test.tsx` |
| `react-test-renderer` | 8 suites (see Task 2) |
| `@testing-library/react` | 5 suites, on v11 |
| `@testing-library/user-event` | **Declared but never imported — dead dependency** |
| `useRef()` with no argument (now a type error) | None; `Gauge.tsx` passes `null` |
| JSX transform | Already `jsx: react-jsx` |

The two worst React 19 removals — `defaultProps` and `propTypes` — do not apply to this codebase.

## Task 1: Upgrade React to 19, keeping every test green

**Files:**
- Modify: `package.json`, `package-lock.json`, `src/index.tsx`, `src/App.test.tsx`

**Interfaces:**
- Produces: a React 19 application whose entire existing suite still runs, including the eight `react-test-renderer` suites.

The ordering here is deliberate. `react-test-renderer@19.1.9` **exists**, so those suites keep working across the version bump. Rewriting them is Task 2. Doing both at once would mean a moved number had two candidate causes and neither could be ruled out.

- [ ] **Step 1: Upgrade the packages**

Run backgrounded. Upgrade together, since their peers are interlocked:

```bash
npm i --legacy-peer-deps \
  react@^19 react-dom@^19 react-test-renderer@^19
npm i -D --legacy-peer-deps \
  @types/react@^19 @types/react-dom@^19 @types/react-test-renderer@^19 \
  @testing-library/react@^16
```

`@testing-library/react@16` declares `react: ^18 || ^19`, so it is the version that supports this.

**Then remove `--legacy-peer-deps` and check whether a clean `npm ci` succeeds.** If it does, drop the flag — Phase 3a removed it deliberately because it suppresses exactly the peer signals this upgrade depends on. If it does not, **report precisely what still conflicts**; the likely candidates are `@types/react-router-dom@5` against `@types/react@19`, or `formik`. Do not leave the flag in place silently.

- [ ] **Step 2: Delete the dead dependency**

`@testing-library/user-event` is declared and never imported. Remove it rather than upgrading it.

- [ ] **Step 3: `src/index.tsx` — `ReactDOM.render` → `createRoot`**

```tsx
import { createRoot } from 'react-dom/client';

const container = document.getElementById('root');
if (container) {
  createRoot(container).render(<App />);
}
```

Keep the existing Sentry block and its `import.meta.env.PROD` guard exactly as they are. Note `src/index.tsx` is excluded from coverage (`vite.config.ts`), so no test exercises this file — **verify it by serving the build and loading the page**, not by a green suite.

- [ ] **Step 4: `src/App.test.tsx` — it uses two removed APIs**

It calls both `ReactDOM.render` and `unmountComponentAtNode`, neither of which exists in React 19. Rewrite it using `@testing-library/react`'s `render`, which handles mounting and cleanup. Keep what the test actually asserts unchanged.

- [ ] **Step 5: Run the suite and account for every difference**

```bash
npm test
```

Baseline from Phase 3a: **158 passed / 3 skipped**, coverage ~99.27% statements.

React 19 may change snapshot output. **Every changed snapshot must be explained before you continue.** For each: what changed, and why React 19 produces it. If you cannot explain one, stop and report — an unexplained snapshot change in this codebase is exactly the shape of the defect that had a test snapshotting a blank form for four years.

Expect deprecation warnings from `react-test-renderer@19`. Those are expected and Task 2 removes them.

- [ ] **Step 6: The gates**

```bash
npx tsc --noEmit
npm run lint
npm run build
SUBJECT_ONLY=1 npm --prefix e2e run setup
SUBJECT_ONLY=1 npm --prefix e2e run replay
```

`SUBJECT_ONLY=1` is required on **both** e2e commands.

**The L2 replay is the gate that matters.** React 19 changes how the app renders; the numbers it renders must not move. If any value moves, **STOP and report BLOCKED** — do not adjust the fixture, do not re-capture, do not add tolerance.

- [ ] **Step 7: Verify the entry point by hand**

`src/index.tsx` is uncovered by tests. Serve `build/` and confirm the app actually mounts — a broken `createRoot` would leave a blank page with a green suite. Report what you saw.

- [ ] **Step 8: Commit**

```bash
git add -A
git commit -m "feat(react): upgrade React 17 to 19"
```

## Task 2: Retire `react-test-renderer`

**Files:**
- Modify: the eight suites below, their snapshots, `package.json`

```
src/patient/CorneaProfile.test.tsx
src/patient/Info.test.tsx
src/matrix/VaultDistributionRows.test.tsx
src/matrix/VaultStatRows.test.tsx
src/matrix/index.test.tsx
src/regression/index.test.tsx
src/normality/Gauge.test.tsx
src/normality/index.test.tsx
```

`react-test-renderer` is deprecated in React 19 and has no future. These suites move to `@testing-library/react`'s `render(...)` and `asFragment()`.

- [ ] **Step 1: Convert one suite first, and study its snapshot diff**

Start with `src/matrix/VaultStatRows.test.tsx`. Convert it, regenerate, and **read the diff carefully**.

`TestRenderer.toJSON()` and `asFragment()` produce structurally different output — the first is a React element tree, the second real DOM. So the snapshot will change substantially and legitimately. Confirm the *content* still describes the same rendered result before converting the rest. Report what the shape change looks like.

- [ ] **Step 2: Convert the remaining seven the same way**

Note `src/normality/index.test.tsx` is `it.skip`-ped and its component takes untyped `{...args}` props — a known gap recorded in Phase 2a. Convert it, but **do not un-skip it**; that is a separate decision with its own risk, and it is not this phase's to make.

`src/patient/CorneaProfile.test.tsx` was fixed in Phase 2a to use real field names; its snapshot is meaningful. Preserve that.

- [ ] **Step 3: Remove the dependency**

```bash
npm uninstall react-test-renderer @types/react-test-renderer
```

Confirm nothing still imports it: `grep -rn "react-test-renderer" src/`.

- [ ] **Step 4: The gates, and the one that matters**

Full suite, `tsc --noEmit`, lint, build, and the L2 replay.

**This is the moment the golden master earns its existence in this phase.** Every snapshot in the repo has now been regenerated — the legacy suite's evidentiary value is temporarily zero, because the snapshots were rewritten from the current behaviour rather than verified against the old. `src/golden/expected.json` is the independent backstop, and it **must not move by a digit**.

If it does: STOP, report BLOCKED, and say exactly which rows and fields moved.

- [ ] **Step 5: Commit**

```bash
git commit -m "test(react): migrate the legacy suites off react-test-renderer"
```
